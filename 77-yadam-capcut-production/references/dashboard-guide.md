# LALA 야담제작 진행현황표 77 자동 열기

## 채팅별 상태 분리 — 모든 호출에서 우선 적용

- `CODEX_THREAD_ID`를 확인하거나 현재 호스트가 반환한 채팅 ID를 `-ChatId`로 전달한다. 다른 채팅의 ID를 추측해서 사용하지 않는다. ID가 없으면 임의의 전역 상태로 돌아가지 말고 현재 채팅을 식별한 뒤 진행한다.
- 도우미가 반환한 `url`에는 `?session=현재채팅ID`가 포함된다. 이 URL을 그대로 오른쪽 인앱에 연다. 쿼리를 지우거나 루트 URL만 열지 않는다. 이미 루트 URL 탭을 열어둔 상태라면 현재 채팅 전용 URL로 이동한다.
- `status_path`와 `current_work_path`는 `state/sessions/현재채팅ID/` 아래다. 현재 채팅의 제작 단계는 이 파일만 갱신한다. 전역 `state/steps.json` 및 `state/current-work.json`은 이전 버전 호환용이며 읽어 현재 작품으로 자동 선택하거나 덮어쓰지 않는다.
- 작품명·길이·진행 상태는 같은 채팅 스냅샷에서 읽는다. 공용 index.html에 작품명을 쓰지 않는다. 사용자가 여러 채팅에서 다른 작품을 제작해도 서로의 현황표를 변경하지 않는다.
- 초기화는 현재 채팅의 파일에만 적용한다. `-NewSession`을 사용해도 다른 채팅과 작품 폴더는 유지된다. 기존 작품을 이어가는 경우 해당 작품의 진행 기록·현황표상태.json을 검증해 현재 채팅 파일로만 복원한다.

## 새 시작과 현황표 재열기 구분

- 단독 명령 `77` 또는 `77 현황표`는 현재 채팅의 현황표 재열기다. `ensure-dashboard.ps1 -ChatId <확인된 현재채팅ID>`를 `-NewSession` 없이 실행하고 반환된 URL을 오른쪽 인앱 패널에 연다. 작품·단계 상태를 유지하며 제작 단계를 실행하지 않는다. 새 스킬 호출 초기화보다 이 규칙을 우선한다.

- 새 스킬 호출로 새 작업을 시작: `ensure-dashboard.ps1 -NewSession`. 현황표만 0/13으로 초기화한다.
- 현황표 오른쪽 위의 **리셋 · 새 이야기** 버튼도 이 채팅의 현황표를 0/13, 작품 선택 전으로 초기화한다. 선택된 작품이 있으면 먼저 작품 폴더의 `현황표상태.json`에 직전 진행 상태를 보관한다. 채널 이름과 다른 채팅의 상태는 유지한다. 화면이 바뀌면 채팅에 `1`을 입력해 새 이야기의 주제·길이 선택을 시작한다.
- “현황표 열어줘”, “다시 보여줘”, “이어서 할게”: `ensure-dashboard.ps1` 옵션 없이 실행. 마지막 작품과 단계 상태를 그대로 표시한다. 스킬을 함께 멘션했더라도 재열기 의도가 우선이다.
- “다음 단계”, 승인·수정, 패널 새로고침: 현황표를 초기화하지 않는다.
- 01~13 번호 옆 녹색 별에 마우스를 올리면 **초기화**가 표시된다. 별을 누르면 해당 단계부터 13단계까지 완료 표시와 결과를 비우고 대기한다. 앞 단계 기록과 원래 제작 파일은 보관한다. 01을 초기화하면 주제·길이 선택 전 상태로 돌아가고, 04를 초기화하면 3단계 대본과 승인 상태를 보관한다. 초기화한 단계는 사용자가 별도의 **시작** 버튼을 눌러 실행한다.
- 패널이 닫혔는지 여부는 새 작업의 근거가 아니다. 서버까지 꺼져 있어도 저장된 state를 유지하며 재실행한 뒤 연다. 서버가 살아 있으면 재사용한다. 열린 동일 URL이 있으면 기존 패널을 재사용한다.
- 재열기 시 현재 채팅의 작품 진행 기록과 마지막 표시 상태가 맞는지 확인한다. 다른 작품 상태가 표시되어 있으면 현재 채팅에서 확정한 작품의 상태를 복원한다. 제작 결과와 필요한 승인을 확인하지 않은 단계를 추측해 완료 처리하지 않는다.

## 스킬 호출 시

1. 사용자가 스킬을 새로 명시 호출하면 Windows에서 scripts/ensure-dashboard.ps1 -NewSession을 실행한다. 같은 작업의 다음 단계·승인·수정이나 단순 화면 재열기는 옵션 없이 실행한다. 기본 작업실은 설정된 작업 루트 아래 야담제작소웹이다. 새 배포본의 현황표 파일은 기존 서버를 닫은 뒤 실행하면 갱신하며, -NewSession에서는 현재 채팅의 상태만 초기화한다. 초기화 직전의 단계 상태는 확인된 기존 작품 폴더의 현황표상태.json에 보존하고, 작품 파일은 변경하지 않는다. 작업실이 없으면 스킬 assets/dashboard에서 기본 화면을 준비한다. 별도 위치가 확정된 경우 -DashboardRoot로 전달한다. Node.js가 없거나 시작 검증이 실패하면 실패를 짧게 알리고 가능한 제작 작업을 채팅에서 계속한다.
2. 반환된 ready=true와 URL을 확인한 뒤 open_in_codex 도구를 찾아 `target: {type: "browser", url: 반환된 URL}, placement: "right"`로 현재 채팅의 오른쪽 인앱 패널에 연다. 다른 채팅 ID를 임의로 지정하지 않는다. 현재 채팅에서 동일 URL 패널이 이미 열려 있으면 중복 탭을 만들지 않고 재사용한다. 서버가 실행 중이어도 패널은 확인한다. 새 채팅에서의 첫 호출에도 적용한다.
3. 패널 열기 도구가 없는 환경이면 URL 링크만 제공하고, 자동으로 열렸다고 말하지 않는다. 외부 브라우저는 자동 실행하지 않는다. 일반 웹페이지에서 현재 Codex 채팅을 자동 실행할 수 있다고 가정하지 않는다.

실행 예시(실제 설치 경로를 사용):

```powershell
& '<현재 스킬 폴더>\scripts\ensure-dashboard.ps1' -ChatId $env:CODEX_THREAD_ID -NewSession
```

스크립트는 새 호출 시 현황표 초기화, 서버 준비·중복 방지·시작 확인을 수행한다. 새 호출은 0/13, 작품 선택 전, 1단계 준비로 시작한다. 현재 채팅 전용 URL에서 작품명과 진행률을 자동 갱신한다. 제작 단계를 자동 실행하거나 사용자의 결정을 대신하지 않는다. 8790 포트가 다른 서비스에서 사용 중이면 해당 서비스를 종료하지 않는다.

## 작품과 상태 동기화

### 현황표에서 단계 실행

- 단계 카드의 **시작**을 누르면 이 PC에 로그인된 Codex 실행기가 해당 단계만 실행한다. 현재 열려 있는 Codex 채팅 작업과 독립적으로 실행하며, 결과는 현황표의 **결과 보기**에서 확인한다. 주제와 길이를 저장하면 2단계 실행을 바로 요청한다.
- 한 채팅의 현황표에서는 한 단계씩 실행한다. 승인이나 자료가 필요하면 결과에 다음 입력을 표시한다. 결과의 안내에 따라 필요한 자료를 준비한 뒤 단계 카드에서 **이어서 실행**을 누른다. 현재 실행기에서 사용할 수 없는 도구가 있으면 결과에 표시한다.
- **결과 보기**는 완료 기록이나 저장된 결과가 있는 단계에 표시한다. 대기나 입력 안내만 있는 단계에서는 숨긴다. 결과 파일 링크와 TXT, 해당 결과에 필요한 안내를 한 번씩 표시한다. **저장 폴더 열기**를 누르면 파일 탐색기에서 폴더가 열리고, 파일 이름을 누르면 Windows 탐색기에서 해당 파일이 선택된다. 가장 앞에 열린 탐색기 창이 같은 폴더를 보고 있으면 그 창에서 선택하고, 다른 폴더를 보고 있으면 대상 폴더를 새 창으로 연다. 4단계는 더빙 원고를 읽는 순서와 글자 수를 보여 준다. 채팅으로 결과를 전달할 때도 저장 폴더와 파일별 링크를 함께 표시한다.
- 1단계 결과는 선택한 주제와 줄거리를 즉시 표시한다. 3단계 하단에는 인트로와 마무리를 제외한 본편 글자 수와 분당 300~340자 기준 예상 낭독 시간을 표시한다. 4단계 분할검증 기록은 폴더에 저장한다. 5단계 결과에는 이미지 기준과 프롬프트, 캐릭터목록, 에셋목록, 기본 화풍참조만 표시한다. 캐릭터목록 파일이 따로 없으면 해당 단계에 등록된 캐릭터 이미지 링크를 펼쳐 볼 수 있다.
- 5단계 에셋목록에는 원본 링크를 표시한다. 6단계 결과에는 씬별 이미지 프롬프트 링크와 ‘이미지 멘션 반영하기’, ‘이미지생성후 파일이름도 씬이름으로 수정’ 안내를 표시한다. **(SRT, MP3 파일 제공)** 안내는 7단계 카드에 표시한다. 사용자가 현재 승인 대본에 대응하는 두 파일을 채팅에 첨부하면 곧바로 7단계를 진행한다. 현황표 실행기에서 작업 중이면 점 세 개가 차례로 움직인다. 실행 출력이 5분간 없으면 점을 멈추고 응답 지연이라고 표시한다. 연결이 끊겼을 때도 점을 멈추고 연결 상태를 표시한다.
- 윈도우에서는 Codex에 로그인한 사용자로 서버를 시작한다. 스크립트는 데스크톱이 제공한 Codex 실행 파일을 우선 사용한다. 별도로 설치한 실행기를 사용할 때는 `YADAM_CODEX_CLI`에 실행 파일의 절대 경로를 지정한다.

### TXT 결과와 채팅 표시

- 각 단계의 **결과 보기 → TXT**에서 작업 결과를 연다. 시놉시스·대본·표·자막 등 글이 담긴 개별 파일은 같은 줄에서 원본과 TXT를 열 수 있다. 개별 TXT가 없으면 단계 결과 TXT를 표시한다.
- TXT를 누르면 현황표에 원문을 펼친다. 공유 Codex 서버에 연결할 수 있으면 연결된 채팅에 원문 표시를 요청한다. 데스크톱 채팅으로 바로 보낼 수 없는 환경에서는 **채팅 요청 복사**를 눌러 같은 채팅에 붙여 넣고 보낸다. 텍스트 자체는 **본문 복사**로 복사한다.
- 작품의 TXT는 `제작관리/단계별결과/`에 UTF-8로 저장한다. 작품을 아직 만들지 않은 상태의 TXT는 해당 채팅 폴더의 `결과TXT/`에 저장한다. 기존 TXT가 결과에 있으면 그대로 읽는다.
- 별도 실행기의 결과는 실행 종료 때 TXT를 준비한다. 현재 채팅에서 작업을 마쳤다면 해당 단계 `steps.json`의 `resultText`에 결과 설명, `resultFiles`에 실제 저장 파일의 프로젝트 기준 상대 경로 또는 `{ "path": "상대 경로", "label": "표시 이름" }`을 적는다. `GET /api/steps/result?session=<현재 채팅 ID>&step=<단계>`의 `txt` 목록에서 생성 여부를 확인한다. 기존 기록도 **결과 보기**를 열 때 TXT가 준비된다.

### 1단계 주제와 영상 길이 선택

- `1`로 새 작업을 시작하면 현재 채팅의 `current-work.json`에 `step: 1`, `status: "awaiting_input"`와 `topicSelection`을 저장하고 `steps.json`의 1단계를 입력 대기로 표시한다. `topicSelection.candidates`에는 번호, 제목, 장르, 분위기, 원전 표시와 줄거리(`number`, `title`, `genre`, `mood`, `origin`, `summary`)를 넣는다. `topicSelection.durationOptions`에는 제작 지침의 네 가지 길이를 넣는다. 확정된 값만 최상위 `topic` 또는 `duration`에 둔다.
- 채팅 전용 현황표를 오른쪽 인앱에 연다. 화면이 기존 화면이면 같은 URL을 새로고침한다. 미정 항목의 라디오 버튼은 빈 상태로 시작하고, 전부 선택했을 때 `선택 저장`을 사용할 수 있다. 선택란은 현재 채팅에서만 표시한다.
- 주제가 미정이면 `topicSelection.alternativeBatches`에 다른 후보 3개씩 두 묶음을 추가한다. `다른 주제 보기`를 누르면 다음 묶음이 현재 후보로 저장되며, 화면에서 고른 영상 길이는 유지된다. 준비한 후보를 다 보면 채팅 안내가 나온다. 사용자가 `다른 주제`라고 보내면 `seenTitles`와 현재 목록의 제목을 피해 새 후보와 추가 묶음을 준비한다. 현재 후보의 제목은 `seenTitles`에 추가하고 `batchNumber`는 1 늘린다. 영상 길이 항목은 유지한다.
- 제출하면 현황표가 해당 채팅의 `topic`, `duration`, `topicSelection.submittedAt`을 저장하고 1단계를 완료로 표시한다. 화면은 즉시 2단계 시놉시스로 이동한다. 연결된 실행기가 2단계 작업을 시작한다. 실행기 연결 없이 채팅에서 이어달라는 요청을 받으면 저장된 주제와 길이로 시놉시스를 작성한다. 현황표에 표시할 짧은 줄거리는 `synopsisSummary`에 기록한다.
- 시놉시스는 작품 폴더의 `제작관리/시놉시스.md`에 저장한다. 파일이 있으면 2단계 카드의 **결과 보기 → TXT**에서 원문을 펼쳐 읽는다. 다른 제작 단계로 넘어가도 선택된 작품의 원문을 같은 곳에서 볼 수 있다.

- 새 호출 직후에는 이전 작품을 자동 선택하지 않는다. 사용자가 기존 작품을 이어가라고 명시했을 때 해당 작품 경로와 진행 기록을 사용한다. current-work.json은 마지막으로 표시한 작품의 힌트이며, 다른 채팅의 작품을 현재 작품으로 임의 선택하는 근거가 아니다.
- 작품이 확인되면 반환된 current_work_path의 topic·duration·projectPath를 현재 진행 기록과 맞춘다. 화면은 이를 읽어 제목과 길이를 자동 갱신한다. 다른 작품으로 바꿀 때는 이전 작품의 단계 기록을 그 작품 폴더의 진행 기록에 보존하고, 새 작품의 실제 진행 상태를 불러온다. 작품을 특정할 수 없으면 필요한 작품명이나 경로만 묻는다.
- 반환된 status_path의 JSON은 문자열 단계 번호를 키로 한 객체다. 기존 다른 단계는 보존하며 실제 시작 시 running, 사용자 승인·자료 대기 시 awaiting_input, 해당 결과의 검증과 필요한 승인이 끝났을 때만 completed를 기록한다. 명시적 새 스킬 호출에서는 상태를 초기화하되, 같은 세션의 단계 실행·승인·수정 및 단순 화면 새로고침에는 초기화하지 않는다. 초기화나 열기만으로 완료 처리하지 않는다. 실패 시 failed를 기록하고 원인을 진행 기록에 남긴다.
- 예: {"1":{"state":"completed"},"2":{"state":"awaiting_input"}}. 현황표가 상태 파일을 주기적으로 읽으므로 상태만 갱신할 때마다 브라우저 재검수·스크린샷을 반복하지 않는다. 화면이 오래된 경우에만 새로고침한다.
- 1~13단계는 production-guide.md를 따른다. 9단계 본편 검수 다음은 10단계 CapCut Web 인계, 11단계 인트로 제작, 12단계 고정화자 영상제작, 13단계 썸네일·업로드 준비다. 10단계의 기본 인계는 나레이션 전용 오디오 트랙과 확정 시간표에 따라 각각 배치한 본편 이미지 클립을 갖춘 웹 편집 초안이다. 서버에 저장된 초안을 확인하고 편집 링크를 기록한다. 이후 제작한 인트로는 I번호 순서로 별도 전달한다. 합본 편집은 사용자가 한다.
- 제작 작업과 선택·승인은 현황표 실행기나 현재 Codex 채팅에서 진행한다. 12번 고정화자 영상제작 카드는 인트로 카드처럼 완료 버튼을 제공한다. 사용자가 외부에서 영상을 완성하면 카드의 완료 버튼을 눌러 확인할 수 있다. 웹 아래의 '최종 폴더 정리·프로젝트 마무리' 버튼은 현재 작품 정리에 사용한다. 사용자의 '다음 단계', '승인', 수정 요청을 현재 작품 진행 기록에 따라 처리한다.

## 새 장면 이미지의 재검수

- 현재 작품의 `이미지폴더/장면` 바로 아래에 SC번호가 맞는 새 파일을 저장한다. 현황표는 기존 연결표의 이미지 SHA-256과 등록된 작업 폴더를 대조한다. 6~10단계(이미지 프롬프트·장면 파일 검증·연결표·렌더링·CapCut 인계)가 모두 완료된 뒤 새 이미지 내용이 확인되면 **새 장면 이미지가 감지되었습니다**를 표시하고, **8~10단계 다시 진행** 또는 **기존 결과 유지**를 선택받는다. 다시 진행을 선택했을 때 해당 단계에 **재검수 필요**를 표시한다. 기존 결과 유지를 선택하면 현재 완료 표시를 유지하고 같은 변경에 다시 묻지 않는다. 어느 경우든 이전 연결표·영상·CapCut 결과와 기존 완료 기록을 보존한다. 본편 작업이 진행 중일 때는 새 이미지나 수정본을 계속 추가할 수 있으며 선택 안내를 표시하지 않는다. 이미 다시 진행을 선택한 경우 작업 중 추가 이미지는 현재 재검수에 포함한다. 같은 내용의 사본이나 이름만 바뀐 파일은 새 이미지 판정에서 제외한다.
- 새 이미지로 8~10단계를 시작하기 전에 현재 채팅의 `/api/snapshot?session=현재채팅ID`에서 `imageReview.revision`을 확인한다. 작업 중에는 기존 완료 항목을 보존한다. 검수가 끝나면 다시 스냅샷을 확인한다. 같은 리비전이면 완료한 단계 항목에 `reviewedImageRevision`과 새 완료 내용을 기록한다. 교체하는 이전 완료 항목은 `previousCompletions`에 추가하고, 결과 파일은 기존 결과와 구별되는 이름으로 저장한다. 작업 중 새 이미지가 추가되어 리비전이 달라졌다면 새 파일을 확인한 후에만 완료로 표시한다.
- 새 이미지로 개별 단계를 확인할 때 해당 단계 표시만 해제한다. 10단계 수동 완료는 8·9단계가 같은 이미지 기준으로 확인된 뒤 사용한다. 최종 폴더 정리의 완료 판정에는 재검수 필요 단계도 포함한다.

## 단계 순서 버전

현재 순서는 workflowOrderVersion=3이다. 버전 2의 썸네일 기록은 12번에서 13번으로 옮기고, 새 12번은 미완료로 둔다. 버전 1은 10→11(인트로), 11→13(썸네일), 12→10(CapCut)으로 옮긴다. 채팅을 열 때 해당 채팅의 기록만 갱신하며 기존 작품의 완료 기록과 종료 여부를 보존한다.

## 이 컴퓨터의 채널 이름

현황표 맨 위에 채널 이름을 입력하고 저장한다. 작업실 `state/channel-profile.json`에 채팅 세션과 별도로 보관하므로 새 채팅과 컴퓨터 재시작 후에도 같은 값을 사용한다. 저장된 값은 `ensure-dashboard.ps1`이 `channel_name`으로 반환한다. 새 설치에서는 채널 이름을 입력할 수 있게 비워 둔다.

## 최종 폴더 정리

하단 버튼은 project-layout.mjs의 사용자 지정 구조(더빙원고·이미지폴더·인트로영상·오디오자막소스·본편최종결과·유튜브업로드 및 제작관리)를 적용한다. 모든 MD·JSON과 원본을 보존하고 파일 이동·문서 링크·JSON·현재 채팅 경로를 갱신한다. 삭제 후보는 확인만 하며 삭제·휴지통 이동을 하지 않는다. 예전 음원·이미지 위치 유지 정책보다 이 구조를 우선한다. 실제 외부 PC 프로젝트의 재연결은 별도이며, 미완료 단계는 완료 처리하지 않는다. assets/dashboard/cleanup.mjs와 project-layout.mjs를 server.mjs와 함께 배포한다. 현재 채팅·작품 경계 및 미리보기 검증 규칙은 유지한다.

## 사용자 종료 버튼

정리 버튼 아래 진한 초록색 '이 프로젝트 종료' 버튼은 단계 자동 완료와 별개다. 외부 CapCut에서 인트로를 제작한 사용자가 눌러 종료한다. `/api/project/close`는 현재 session과 확인한 projectPath를 검증하고 현재 작품의 종료 상태를 저장한다. 개별 검증 단계와 모든 파일은 보존한다. 종료 안내 문구는 '100만유튜버 화이팅!! 새채팅에서 프로젝트를 시작해주세요'이며, 글자색은 오렌지(#a63f13)로 표시한다. 새 채팅은 자동 생성하지 않으며, 현재 작품을 자동 초기화하지 않는다.

## 종료 후 계속하기와 10~12단계 완료

종료된 프로젝트도 같은 채팅에서 추가 작업을 요청하면 재개한다. 재개 버튼은 만들지 않는다. 10~12단계 카드의 완료 버튼은 `/api/steps/complete`에서 현재 session·projectPath·단계 번호를 검증하여 사용자 확인으로 저장한다. 허용 단계는 10, 11, 12이며 completionSource=user로 구분한다. 종료 후 새 완료 표시·폴더 정리 또는 채팅의 추가 작업으로 재개할 수 있다. 종료 여부만으로 편집·정리를 잠그지 않는다.
