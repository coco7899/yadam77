# 야담 유튜브 제작과 CapCut 편집 준비

[야담 제작 지침](references/production-guide.md)의 공통 지침과 요청한 단계에 해당하는 절을 읽는다. 전체 제작에서는 확정된 주제·대본·스타일·장면 목록을 재사용하고 해당 단계부터 이어간다. 사용자가 촬영 기획표나 프롬프트만 요청한 경우에는 그 결과를 바로 작성한다. 작품이나 확정 버전을 특정할 수 없으면 임의로 선택하지 않는다.

## 현황표 재열기 명령 77

- 사용자가 채팅에 `77`만 입력하거나 `77 현황표`라고 하면 현재 채팅의 현황표를 다시 연다. 스킬을 새로 멘션하지 않아도 적용하며, 새 제작 시작이나 제작 단계 실행으로 해석하지 않는다.
- [현황표 연결 지침](references/dashboard-guide.md)에 따라 확인된 현재 채팅 ID로 `scripts/ensure-dashboard.ps1 -ChatId <현재채팅ID>`를 실행한다. `-NewSession`은 사용하지 않는다. 반환된 URL을 `open_in_codex`의 browser 대상, right 배치로 열고 기존 작품·진행 상태를 유지한다.
- 서버나 패널이 꺼져 있어도 저장된 상태를 유지하며 복구한다. 현재 채팅에 저장된 작품이 없으면 작품 선택 전 현황표만 열고 다른 채팅의 작품을 가져오지 않는다.
- `77`은 재열기 전용 명령이다. 아래의 새 스킬 호출 초기화 규칙보다 우선하며, `1`의 제작 시작·이어가기 규칙과 구분한다.

## 호출 시 인앱 현황표 자동 열기

- **채팅별로 분리:** `CODEX_THREAD_ID` 또는 현재 채팅의 확인된 ID를 `-ChatId`로 전달한다. 반환된 `?session=채팅ID` URL과 `status_path`·`current_work_path`만 사용한다. 전역 `state/steps.json`·`state/current-work.json` 또는 다른 채팅 파일을 갱신하지 않는다. 작품명은 상태 JSON에서 읽으며 공용 HTML에 특정 작품을 고정하지 않는다.

- 사용자가 이 스킬을 새로 명시 호출하면 [현황표 연결 지침](references/dashboard-guide.md)에 따라 **LALA 야담제작 진행현황표 77**를 새 세션으로 초기화하고 현재 채팅 오른쪽 인앱 패널에 자동으로 연다. 새 호출의 기본 표시는 **0/12 완료·작품 선택 전·1단계부터 준비**다. 직전 작품의 완료 상태를 자동으로 가져오지 않는다.
- 새 호출에서는 `scripts/ensure-dashboard.ps1 -NewSession`을 실행한다. 같은 작업 중 '다음 단계', 승인, 수정 요청이나 단순 새로고침에는 초기화 옵션을 사용하지 않는다. 사용자가 명시적으로 기존 작품을 이어 달라고 하면 그 작품의 진행 기록을 불러와 표시한다.
- 작업 중 “현황표 열어줘”, “현황판 다시 보여줘”, “닫힌 현황표 다시 열어줘”는 **재열기 요청**이다. 이때는 `scripts/ensure-dashboard.ps1`을 **-NewSession 없이** 실행하고, 해당 작업의 마지막 작품·진행 상태를 유지한 채 오른쪽 인앱에 다시 연다. 사용자가 스킬 이름을 함께 멘션해도 요청 의도가 재열기·이어서 작업이면 초기화하지 않는다.
- 초기화 대상은 현황표의 선택 작품·길이·진행 상태뿐이다. 기존 작품 폴더, 승인 대본, 음원·이미지·제작 기록은 보존한다. 이미 열린 탭은 초기화 후 새로고침해 재사용한다.
- 반환된 URL을 `open_in_codex`의 browser 대상과 right 배치로 연다. 도구나 실행 환경이 지원하지 않으면 실제 한계를 알리고 링크를 제공한다.
- 웹은 오렌지 톤의 12단계 현황표다. 제작 작업은 현재 채팅에서 진행하고, 맨 아래의 최종 폴더 정리 버튼은 현재 작품 정리에만 사용한다. 1~12단계는 제작 지침을 따른다. 후반 순서는 9단계 본편 검수 → 10단계 CapCut으로 보내기 → 11단계 인트로 제작 → 12단계 썸네일·업로드 준비다. 단계 시작·입력 대기·검증 완료에 맞춰 상태를 갱신하며, 사용자 승인 전이나 필요한 파일을 기다리는 동안에는 완료로 표시하지 않는다.

## 단계 제목 표시

- 6단계의 현황표 표시는 첫 줄 `이미지프롬프트생성`, 둘째 줄 `(SRT,MP3파일제공)`으로 고정한다. 단계 제목도 **6단계. 이미지프롬프트생성**으로 쓴다. 최종 SRT·MP3를 받아 장면·시간과 촬영 기획표·이미지 프롬프트를 만드는 기존 작업 범위는 유지한다.

- 제작 단계에 들어가거나 재개할 때 사용자에게 보여주는 첫 안내와 결과 상단에 현재 단계 번호와 제목을 표시한다. 제작 지침의 1~12단계 번호를 사용한다. 예를 들어 **4단계. 더빙용 원고 확정**처럼 쓴다.
- 한 응답에서 여러 단계를 수행하면 각 단계의 시작과 결과를 구분할 수 있도록 해당 번호와 제목을 표시한다. 짧은 단계 내 진행 안내마다 같은 제목을 반복하지 않는다.
- 대본 단계의 세부 작업은 **3-A단계. 1차 대본 작성**, **3-B단계. 첫 번째 검수 — 개연성과 사건 연결**, **3-C단계. 두 번째 검수 — 몰입과 구연감**, **3-C 추가 검수. 야담 구연체와 낭독 호흡**, **3-D단계. 개정본 확인·확정**으로 표시한다.
- 선택 카드의 질문에도 해당 단계 번호와 제목을 포함한다. 진행 상태와 다음 작업을 안내할 때는 실제 완료·대기 상태에 맞는 번호를 쓴다. 작품에 관한 일반 질문은 답변에 맞춰 설명한다.

## 빠른 실행 1

- 사용자가 이 스킬을 멘션하면서 숫자 1만 적거나, 이 스킬을 호출한 직후 같은 채팅에서 1만 보내면 바로 시작한다. 새 작업이면 1단계에서 미정인 주제와 길이를 카드로 제시한다. 주제와 길이가 모두 미정이면 한 카드에 두 개의 단일 선택 질문을 넣는다.
- 현재 작업의 작품과 진행 상태가 확인되면 확정 자료를 사용해 다음 단계부터 이어간다. 사용자가 지정한 작업 범위와 이미 확정한 선택을 적용한다. 진행에 필요한 자료가 빠져 있으면 해당 자료만 요청한다.
- 단독 숫자 1 앞에 현재 야담 작업의 선택지가 제시되어 있으면 그 선택지의 답으로 처리한다. 이 스킬을 호출하지 않은 다른 작업의 숫자 1에는 적용하지 않는다.

## 프로젝트 위치와 최종본 저장

- 별도 지정이 없으면 [제작 지침의 작업 루트](references/production-guide.md#프로젝트-위치와-파일-유지) 아래 `야담작업\작품제목`에 작품별로 모은다. 기존 작품은 진행 기록에서 실제 경로를 찾아 재사용하며, 사용자가 옮기라고 요청하면 참조 경로도 함께 갱신한다.
- 모든 과정에서 최종 산출물만 보관한다. 수정할 때 같은 최종 파일을 갱신하고 초고·이전 수정본·실패 생성물·임시 스크립트·불필요한 백업을 완료 후 남기지 않는다. 검수 과정의 초고 비교는 메모리나 작업 중 임시 자료로 하며, 최종 검수 요약과 제작 재개에 필요한 정보만 현재 진행 기록에 반영한다.
- 서로 다른 장면·인물·소품 상태의 참조와 더빙 분할 파일 등 각각 필요한 최종 자료는 유지한다. 원문 매칭·타임코드·실제 참조 경로·검증 정보도 최종 제작 데이터로 보관한다. 사용자가 제공한 원본은 단순히 이전 버전처럼 보인다는 이유로 삭제하지 않는다.

## 프로젝트 표준 폴더와 최종 정리

사용자가 확정한 아래 구조를 새 작품의 기본 저장 구조로 사용하고 기존 작품 정리에도 적용한다.

```text
작품제목/
├─ 더빙원고/본문종합, 분할더빙원고
├─ 이미지폴더/캐릭터, 에셋, 장면
├─ 인트로영상/인트로이미지, 인트로영상
├─ 오디오자막소스/SRT, MP3
├─ 본편최종결과/
├─ 유튜브업로드/
└─ 제작관리/
```

- 본문종합에는 승인 본문·종합 더빙 원고, 분할더빙원고에는 분할 TXT와 분할 검증 JSON을 둔다. 스타일참조·제공원본·장면 제작자료는 이미지폴더 내부에, 인트로 기획·프롬프트는 인트로영상/제작자료에, CapCut 인계·본편 검수는 본편최종결과 내부에 둔다.
- 기타 MD·JSON은 관련 제작 폴더 또는 제작관리에 반드시 보존한다. 루트에는 00_제작진행.md·프로젝트안내.md·현황표상태.json을 둔다. 작업 재개 시 고정된 옛 경로보다 진행 기록과 실제 파일 경로를 먼저 확인한다.
- 현황표 맨 아래 `최종 폴더 정리·프로젝트 마무리` 버튼은 위 구조로 이동할 대상을 먼저 보여주고 실행한다. 삭제 후보는 확인만 하며 자동 삭제·휴지통 이동을 하지 않는다. 이름에 수정·초안이 있다는 이유로 미사용으로 판단하지 않는다. 실제 삭제는 별도 사용자 지시가 있을 때만 수행한다.
- 이동할 때 프로젝트 내 MD·JSON·연결표·현재 채팅 상태의 참조를 갱신하고 원본 미디어의 내용이 바뀌지 않았는지 검증한다. 외부 PC CapCut의 기존 로컬 경로를 자동으로 바꿨다고 주장하지 않는다. 미완료 제작 단계는 유지한다.

## 사용자 프로젝트 종료

- 현황표의 최종 폴더 정리 버튼 아래에 진한 초록색 `이 프로젝트 종료` 버튼을 둔다. 인트로를 외부 CapCut에서 별도 제작하므로 현황표의 모든 단계가 완료되지 않아도 사용자가 직접 종료할 수 있다.
- 클릭하면 현재 채팅의 선택 작품만 `projectStatus=closed`, `status=closed`, `closedBy=user`와 종료 시각으로 저장하고 작품 진행 기록·현황표상태.json에도 반영한다. 개별 단계의 검증 상태는 보존하며 실제 검증되지 않은 단계를 completed로 바꾸지 않는다. 파일 삭제·이동을 실행하거나 기존 작품 상태를 초기화하지 않는다.
- 종료 후 정확히 `100만유튜버 화이팅!! 새채팅에서 프로젝트를 시작해주세요`를 표시한다. 다음 이야기는 사용자가 새 채팅에서 시작한다. 이 버튼 클릭만으로 새 채팅을 자동 생성하거나 다른 채팅·작품을 초기화하지 않는다. 종료된 작품을 재열면 종료 상태와 안내를 유지한다.

- 종료 저장이 성공해 안내문을 표시할 때 색색의 폭죽 효과를 약 4.5초간 한 번 재생한다. 반복 재생·소리·조작 차단은 하지 않으며, 움직임 줄이기 설정에서는 정적인 축하 아이콘만 표시한다. 새로고침이나 종료 작품 재열기만으로 폭죽을 다시 재생하지 않는다.

## 종료 후 추가 작업과 사용자 단계 완료

- 프로젝트 종료는 기록상의 마무리이며 추가 작업을 잠그는 기능이 아니다. 사용자가 종료된 작품의 추가 작업을 요청하면 기존 폴더·확정 자료를 재사용하고 현재 채팅의 projectStatus를 in_progress, status를 running 또는 awaiting_input으로 갱신하며 resumedAt을 기록한다. 이전 closedAt은 이력으로 보존한다. 별도 재개 버튼을 만들거나 재개 승인을 요구하지 않는다.
- 현황표 10단계 CapCut으로 보내기와 11단계 인트로 제작 카드에는 사용자가 누를 수 있는 완료 버튼을 둔다. 클릭 시 해당 단계만 completed로 저장하고 completionSource=user 및 completedAt을 기록한다. 외부 작업의 사용자 확인으로 취급하며 도구로 직접 검증했다고 주장하지 않는다. 다른 단계·다른 채팅의 기록은 보존한다.
- 종료 후에도 정리와 10·11단계 완료 버튼을 사용할 수 있다. 새로 완료를 표시하거나 추가 정리를 실행하면 같은 작품 작업 상태로 이어진다. 종료 안내 아래에도 같은 채팅에서 언제든 추가 작업이 가능함을 알린다. 새 이야기만 새 채팅에서 시작한다.

## 사용자 입력을 줄이는 진행 방식

- 주제를 제안할 때마다 제목 옆에 이야기의 핵심 갈등과 해결 방식에 가장 잘 맞는 장르와 분위기를 추천·표기한다. 구체적인 표기와 분류 기준은 제작 지침의 1단계를 따른다.

- 전체 제작에서는 한 번에 가능한 단계를 진행한다. 주제가 없으면 후보 3개와 추천안을 한 번 제시한다. 주제나 원전이 이미 정해졌으면 바로 시놉시스를 작성한다. 길이가 미정이면 30분, 40분, 1시간, 시나리오에 맞게 중 하나를 라디오 버튼으로 고른 뒤 시놉시스와 대본을 준비한다. 길이가 확정됐으면 다시 묻지 않는다. 스타일은 기존 설정을 우선하고, 미정이면 제작 지침의 기본값을 적용해 알린다. 더빙 원고는 10,000자까지 한 묶음으로 제공하고, 그보다 길면 묶음당 10,000자 이하로 나눈다.
- 시놉시스는 작품 제목 바로 아래에 **짧은 줄거리**를 첫 항목으로 둔다. [제작 지침의 2단계](references/production-guide.md#2단계-시놉시스)에 따라 주인공의 마지막 선택과 실제 결말까지 포함한다.
- 시놉시스 설계와 대본 집필 전에 [제작 지침의 독립 단편 설계 및 검수](references/production-guide.md)를 적용한다. 확인 가능한 이전 작품이 있으면 핵심 사건의 순서와 해결 방식을 비교하고, 중반 전환·마지막 선택의 결과·결말과 마무리의 역할 구분을 두 차례 검수에도 연결한다. 비교 자료가 없으면 확인한 범위만 표시하고 작업을 진행한다.
- 시놉시스와 1차 전체 대본을 쓸 때 제작 지침의 본편 작성 원칙을 적용해, 청자가 인물의 다음 선택과 결과를 궁금해하도록 장면을 설계한다. 1차 대본을 작업 중 구분한 뒤 두 차례 검수하고, 3-D에 앞서 야담 구연체와 낭독 호흡을 한 번 더 검수한다. 검수 완료 후 프로젝트에는 최신 대본 한 편만 남긴다. 첫 검수는 사건 순서·인과·동기·단서의 개연성을 확인해 수정한다. 두 번째 검수는 고친 원고를 처음 듣는 청자 관점에서 읽어 몰입과 구연 리듬을 다듬고, 수정이 앞뒤 설정과 충돌하지 않는지 확인한다. 추가 검수에서는 발화 원고 전체를 낭독하듯 읽고, 연달아 나오는 ‘~습니다’ 계열 어미와 숨이 차거나 자주 끊기는 문장을 입말에 맞게 고친다. 개정 대본 한 편과 짧은 검수 결과를 함께 제시한다. 사용자의 대본 검토는 한 번으로 묶고, 실제 더빙용 원고는 승인 대본으로 확정한다. 승인 대본과 일치하는 최종 더빙을 받으면 다음 단계로 이어간다.
- 파일이 더 필요한 동안 독립적으로 진행할 수 있는 작업을 준비한다. 외부 생성은 이미 정해진 담당과 도구를 따른다. 확인할 자료가 없으면 필요한 자료와 파일 번호만 묶어 요청한다. 로컬에 있는 자료는 경로로 받아 재사용하며, 명확하게 대응되는 파일의 재업로드나 수동 이름 변경을 요구하지 않는다.
- 프로젝트 폴더의 제작 진행 기록을 업데이트한다. 확정 설정·대본 버전·단계 상태·실제 파일 경로·다음에 필요한 입력을 남긴다. 같은 채팅의 새 메시지나 다른 채팅의 경로 지정으로 이어갈 때 이 기록을 먼저 사용한다.
- 완성된 자료의 매칭·연결표·본편 렌더링·검수는 연속해서 진행한다. 9단계 본편 렌더링에서는 움직임이 어울리는 컷에 좌→우·우→좌 이동과 서서히 확대를 골고루 배치한다. 공간 컷은 좌→우를 기본으로, 단서 컷은 인물의 시선 방향 이동이나 단서 중심의 느린 확대를 쓰고, 중요한 대사나 표정은 고정한다. 10단계에서는 효과를 반영한 검수본 MP4로 인계한다. 컷별 편집이 가능한 초안은 지원되는 범위에서 위치·배율 키프레임을 함께 적용하고 재생을 확인한다. 인트로가 필요한 경우에는 본편 렌더링을 기다리지 않고 승인 대본과 참조 설정으로 계획한다. CapCut에서의 합본 편집은 사용자에게 맡긴다.

## 클릭으로 선택하기

- 어느 단계에서든 사용자의 결정이 실제로 필요할 때는 현재 환경의 단일 선택 UI(라디오 버튼)를 우선 사용한다. 기본값을 적용하거나 기존 확정 자료로 진행할 수 있으면 선택창을 띄우지 않는다.
- Codex에서 `request_user_input_async`를 사용할 수 있으면 options로 선택지를 전달한다. 그 환경에서 단일 선택을 지원하는 다른 도구만 제공되면 해당 도구의 형식을 따른다. UI 도구를 사용할 수 없을 때는 채팅에 번호·옵션 이름을 표시한다.
- 추천안을 첫 번째에 두고 표시한다. 사전 선택은 제출이나 승인으로 처리하지 않는다. 주제·길이 선택, 대본 승인·수정, 모호한 파일의 대응, 인트로 진행·생략, 썸네일 조합처럼 닫힌 선택에 적용한다. 수정 내용·파일 경로·새 주제처럼 열린 입력은 자유 입력을 받는다.
- 함께 골라야 하는 항목은 한 번의 카드 호출에 묶되, 별도 기본값이 있는 부수 선택은 추가 클릭을 요구하지 않는다. 답을 받으면 같은 선택을 다시 묻지 않고 작업을 이어간다. 번호나 옵션 이름을 채팅으로 입력해도 같은 결정으로 처리한다.

- 12단계는 썸네일 문구와 영상 제목을 3개씩 1:1로 묶어 먼저 제안하고, 라디오 버튼으로 고른 조합을 제출받은 뒤 썸네일 이미지를 생성한다. 상세 순서는 [12단계 제작 지침](references/production-guide.md#12단계-썸네일유튜브-업로드-준비)을 따른다.

## 촬영 기획표

- 본편은 6단계, 인트로는 11단계를 적용한다. 확정된 씬 개수·번호·순서·대사를 보존한다. 이미 확정된 씬 목록으로 기획표만 작성할 때 MP3·SRT가 없더라도 진행한다. 본편의 실제 표시 시간과 렌더링에는 최종 MP3·SRT를 사용한다.
- 이미지 프롬프트를 쓰기 전에 씬의 감정·행동·대사·인물 관계와 앞뒤 연결을 검토한다. 씬마다 대표 구도 하나와 이미지 한 장을 계획하고, 확정한 앵글·샷 크기·인물 배치를 프롬프트에 직접 적는다. 같은 구도가 시선과 관계를 잘 보여주면 반복한다.
- 촬영 기획표는 씬 번호 / 장면 목적 / 앵글과 샷 크기 / 인물 배치 / 선택 이유 / 첫 프레임 이미지 프롬프트·출처의 여섯 열로 작성한다. 본편과 인트로 첫 컷에는 독립 영문 이미지 프롬프트를, 인트로 후속 컷에는 직전 컷 영상의 마지막 프레임을 출처로 적는다. 기획표만 요청받으면 표 작성으로 마친다.
- 본편 이미지는 대응 발화 구간의 대표 순간을 담는다. 인트로는 컷의 실제 시작 자세와 구도부터 설계한다. 영상은 고정 또는 주요 무빙 하나를 기본으로 하며, 움직일 때는 방향·속도·끝 구도를 적는다. 11단계를 실행하면 첫 컷용 16:9 시작 이미지 한 장을 같은 작업에서 바로 생성해 프로젝트의 인트로영상/인트로이미지에 저장하고 보여준다. 승인된 시작 이미지가 있으면 재사용하며, 사용자가 기획표나 프롬프트만 요청한 경우에는 해당 자료만 제공한다. 후속 컷은 직전 영상의 마지막 프레임에서 이어가며, 영상 프롬프트는 컷별로 나누어 제공한다. 인트로의 대사·행동에 맞춘 샷 전환, 카메라 움직임과 인물별 목소리 고정은 [11단계 인트로 제작](references/production-guide.md#11단계-인트로-제작)을 따른다.

## 이미지 스타일 기본값

- **극사실적 실사 배경·손그림 2D 애니메이션 인물·한국 시대문화**를 기본으로 적용한다. [제작 지침 5단계](references/production-guide.md#5단계-이미지-스타일캐릭터-시트)와 [사용자 기준 이미지](assets/style/실사배경_애니인물_예시.png)를 함께 참고한다. 한국의 복식·머리 모양·건축·소품은 작품의 시대와 인물의 신분에 맞춘다. 사용자가 현재 작품에 따로 정한 화풍이 있으면 그 결정을 따른다.

## 반복 장소·소품 참조 에셋

- 5단계에서 승인 대본을 읽고 반복 등장하는 장소·소품·배경 요소 중 외형과 공간 배치를 고정할 항목을 골라 캐릭터 시트와 함께 실제 참조 이미지를 제작한다. MP3·SRT를 기다리지 않아도 된다. 기존 에셋은 재사용하고 일회성 요소까지 모두 생성하지 않는다.
- 에셋 ID·파일 경로·멘션 별칭·고정 특징·상태 변화를 프로젝트 에셋 목록에 기록한다. 구체적인 제작과 멘션 규칙은 [제작 지침의 5·6단계](references/production-guide.md)를 적용한다.
- 6단계 촬영 기획표의 여섯 열은 유지하며 마지막 열과 복사용 프롬프트에 해당 씬의 참조 캐릭터와 에셋 멘션을 함께 적는다. 등록 전 별칭과 실제 도구 멘션을 구분하며 실제 생성 시 해당 이미지를 첨부·선택한다.

## 더빙 자료를 받는 시점

4단계에서 승인 대본의 더빙용 원고를 추출·분할·확정하고, 5단계에서는 이미지 스타일과 외형을 정해 내장 이미지 도구로 캐릭터 시트와 반복 장소·소품 참조 에셋을 직접 생성·검수하고 프로젝트 폴더에 저장한다. 프롬프트만 요청한 경우에는 그 범위에 맞춘다. 6단계에서 실제 장면 시간 설계에 필요한 최종 MP3와 대응 SRT를 받는다. 이미 제공된 음원과 자막은 재사용한다. 앞선 단계에 미완료 작업이 있으면 현재 완료 범위와 함께 정확히 안내한다.

## CapCut 편집용 결과

검수된 본편 MP4와 제작한 인트로 클립을 별도 파일로 전달한다. 인트로 편집 순서는 I번호로 안내한다. 본편 장면 연결표와 SRT는 본편 0초 기준으로 유지한다. 본편과 인트로의 최종 편집은 사용자가 CapCut에서 진행한다.
